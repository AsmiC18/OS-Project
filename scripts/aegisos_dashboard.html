What the system does

Three connected parts, with clear boundaries between live measurements and simulation.

Monitor real processes

Reads Linux /proc snapshots, calculates sampled CPU usage, records memory use, and logs process lifecycle events.

Control two test workloads

Launches foreground and background commands in systemd scopes and changes their relative CPUWeight values when the adaptive rule triggers.

Compare policies in simulation

Runs controlled scenarios and measures foreground p95 latency, deadline misses, background completions, and utilization.

Implementation map

How the code fits together

Use this page to explain the implementation without opening files during the presentation.

Live monitor and controller

scripts/aegisos_live.py reads /proc, records snapshots/events, and has monitor and managed run modes.

Workload generator

scripts/cpu_burn.py creates a bounded CPU-intensive workload for controlled live tests.

Browser dashboard

scripts/aegisos_dashboard.py serves this UI and JSON APIs; this page visualizes both live logs and experiment results.

C simulator

src/aegisos_sim.c implements simulated scheduling policies and workload events.

CLI and tests

src/main.c exposes simulator commands; tests/ covers simulation, monitor, and dashboard behaviour.

Experiment analysis

scripts/analyze_results.py summarizes raw simulation output and generates tables/plots in results/.

Five scheduling policies

These policy names refer to the simulator unless explicitly marked as the live systemd controller.

Equal

Shares CPU fairly between foreground and background when both contend.

Fixed high share

Gives the foreground a fixed larger share during contention.

Foreground priority

Strongly prioritizes foreground work.

Background cap

Uses a strict simulated cap on background CPU work; not equivalent to CPUWeight.

Adaptive

Adjusts foreground share based on recent latency and queue depth within configured bounds.
